# PAB 상품화 로드맵

## 1. 문서 목적

PAB를 교회 예배용 찬양·성경 발표 프로그램에서 실제 판매 가능한 Windows 제품으로 발전시키기 위한 실행 계획이다.

목표 제품은 다음과 같다.

- 찬양과 성경 구절을 빠르게 검색한다.
- 예배 순서를 구성하고 미리 확인한다.
- PowerPoint 또는 자체 발표 화면으로 출력한다.
- 웹사이트에서 설치 파일을 다운로드하고 바로 사용할 수 있다.
- 사용자는 웹사이트에서 회원가입, 결제, 라이선스 관리를 할 수 있다.

## 2. 현재 상태

### 현재 기술

- C# WPF 데스크톱 애플리케이션
- .NET Framework 4.8
- 구형 Visual Studio 프로젝트 형식
- PowerPoint Interop 기반 출력
- PowerPoint가 없을 때 자체 WPF 발표 화면 제공
- Newtonsoft.Json 사용
- 네이버 VIBE API 및 자체 서버 의존
- MAC 주소 기반 사용 권한 확인
- 실행 시 버전 확인 및 자동 업데이트 로직 존재

### 현재 장점

- 실제로 실행 가능한 제품 기반이 있음
- 검색, 성경 조회, 발표 목록, 가사 수정, 발표 출력 기능이 이미 존재함
- 실제 사용 흐름이 명확함
- WPF 기반이라 Windows 제품으로 확장하기 쉬움

### 현재 주요 위험

- 서버 연결이 시작 단계부터 강하게 요구됨
- HTTP 주소와 오래된 네트워크 코드 사용
- MAC 주소 기반 인증은 교체·복제·개인정보 측면에서 취약함
- 전역 static 상태로 인해 테스트와 확장이 어려움
- PowerPoint 설치 여부에 따라 기능이 달라짐
- 데이터와 API 사용 권한의 상업적 이용 가능 여부 확인 필요
- 기존 서버와 찬양 데이터의 상업적 사용 권한 확인 필요

## 3. 제품 방향

### 핵심 사용자

- 소규모 교회 예배 담당자
- 찬양 인도자
- 영상·방송 담당자
- 예배 순서를 준비하는 목회자 및 운영자

### 핵심 가치

복잡한 발표 프로그램을 배우지 않아도 예배용 찬양과 성경 화면을 빠르게 준비할 수 있게 한다.

### 초기 제품 범위

첫 유료 버전에는 다음 기능을 포함한다.

- 찬양 검색
- 성경 구절 검색
- 예배 순서 목록 작성
- 순서 변경 및 삭제
- 가사·본문 수정
- 배경 이미지 설정
- 자체 발표 화면
- PowerPoint 출력
- 발표 목록 저장 및 불러오기
- 사용자 로그인 및 라이선스 확인
- 자동 업데이트

초기 버전에서는 모바일 앱, 실시간 협업, 복잡한 교회 관리 기능은 제외한다.

## Phase 2. 기술 기반 업그레이드

### 목표

오래된 프로젝트 구조를 유지보수 가능한 Windows 앱 구조로 개선한다.

### 권장 방향

- .NET Framework 4.8에서 .NET 8 WPF로 단계적 이전
- SDK 스타일 `.csproj` 전환
- CommunityToolkit.Mvvm 도입 검토
- `async/await` 기반 HTTP 통신
- API 클라이언트와 화면 코드 분리
- 설정 저장 서비스 분리
- 발표 엔진 인터페이스 도입
- PowerPoint 출력과 WPF 출력 구현 분리
- 의존성 주입 구조 도입 검토

### 권장 구조

```text
PAB
├─ PAB.App                 앱 시작 및 의존성 구성
├─ PAB.Core                도메인 모델과 인터페이스
├─ PAB.Application        검색·발표·라이선스 업무 로직
├─ PAB.Infrastructure      HTTP, 파일, 설정, PowerPoint 연동
├─ PAB.Desktop             WPF 화면과 ViewModel
└─ PAB.Tests               단위 테스트
```

처음부터 프로젝트를 여러 개로 나누기 어렵다면 현재 프로젝트 안에서 `Core`, `Services`, `ViewModels`, `Views` 폴더를 먼저 분리한다.

### 완료 기준

- UI가 서버 호출이나 PowerPoint COM 객체를 직접 다루지 않음
- 검색·발표·라이선스 기능을 독립적으로 테스트할 수 있음
- 기존 기능이 새 구조에서도 동작함

## Phase 3. UI/UX 개편

### 목표

처음 사용하는 교회 운영자도 쉽게 이해할 수 있는 제품 화면을 만든다.

### 화면 구성

```text
┌──────────────────────────────────────────────┐
│ 로고 | 예배 목록 | 설정 | 계정 상태           │
├──────────────┬────────────────┬──────────────┤
│ 검색 결과     │ 본문 미리보기   │ 발표 순서     │
│              │                │              │
│ 찬양/성경     │ 가사/성경 내용  │ 드래그 정렬   │
├──────────────┴────────────────┴──────────────┤
│ 배경 | 글꼴 | 크기 | 발표 시작 | 저장           │
└──────────────────────────────────────────────┘
```

### 작업

- 메인 화면 레이아웃 재설계
- 검색 결과와 발표 목록의 시각적 구분
- 드래그 앤 드롭 순서 변경
- 발표 전 미리보기 추가
- 빈 상태, 로딩 상태, 오류 상태 디자인
- 다크 모드 검토
- 키보드 단축키 제공
- 배경·글꼴 설정을 별도 패널로 정리
- 예배 목록 저장 및 불러오기
- 발표 화면에 제목, 진행 상태, 슬라이드 번호 표시

### 완료 기준

- 신규 사용자가 별도 설명 없이 검색부터 발표까지 수행 가능
- 주요 버튼과 상태가 명확함
- 화면 크기 변경에도 레이아웃이 깨지지 않음

## Phase 6. 결제 및 라이선스

### 목표

웹사이트에서 결제한 사용자가 데스크톱 앱을 정식으로 사용할 수 있게 한다.

### 결제 흐름

```text
회원가입
  ↓
요금제 선택
  ↓
결제
  ↓
서버에서 구독·라이선스 생성
  ↓
앱 로그인
  ↓
라이선스 확인
  ↓
기능 사용
```

### 권장 라이선스 방식

- MAC 주소 단독 인증은 사용하지 않음
- 계정 기반 인증을 기본으로 사용
- 기기 등록 수 제한을 별도로 둠
- 일정 기간 오프라인 사용 허용
- 서버 장애 시 기존 사용자를 즉시 차단하지 않음
- 라이선스 상태를 서버에서 관리

### 초기 요금제 예시

- 무료 체험: 기간 제한 또는 기능 제한
- 개인/소규모 교회: 월 구독
- 교회용: 연 구독
- 여러 PC 사용: 기기 수에 따른 상위 요금제

실제 가격은 사용자 인터뷰와 운영 비용을 확인한 뒤 결정한다.

## 7. 의사결정 원칙

- 기능보다 사용자의 예배 준비 시간을 줄이는 것을 우선한다.
- 서버가 잠시 중단되어도 앱 전체가 종료되지 않게 한다.
- 결제보다 먼저 무료 사용 경험을 완성한다.
- PowerPoint가 없어도 핵심 발표 기능은 제공한다.
- 계정과 라이선스는 MAC 주소보다 안정적인 방식으로 관리한다.
- 새 기능을 추가하기 전에 실제 교회 사용자에게 필요한지 확인한다.
- 모든 큰 변경은 별도 Git 브랜치에서 작업하고 실행 가능한 상태를 유지한다.
